# Presentation release checklist

This is the release-candidate checklist, not confirmation of publication.
The maintainer owns review, commits and deployment. Preserve the procedural
cow, content-pack refactor and the subsequent route-feedback/palette changes.

## Scope for the presentation

Keep the authored procedural cow: 414 triangles, no model/texture download,
and the same shared factory and idle rig. The purchased model is retired
following the maintainer's licence decision and excluded from runtime assets.
Keep the original watermark on the opening film; do not crop or obscure attribution.
Confirm rights before treating the film as cleared for client distribution.
If rights cannot be established, prepare an approved replacement or a verified
film-free package; merely skipping the film does not remove it from publication.

Retain the nine dairy lessons, stable quiz answers, old save keys, certificate,
optional zero-point demonstrations and non-WebGL route. The independent topic
fixture demonstrates reuse; it is not a finished second client module.

## Maintainer's release gate

1. Review the preserved work and this release's packaging/privacy corrections.
2. Confirm unit tests, normal browser tests, 4x CPU-throttled browser tests,
   upstream vendor equality and actual packaged-prefix smoke. Current-run
   results belong in IMPLEMENTATION-NOTES.md; historical counts are not evidence
   of a later build. CI's vendor comparison remains a separate gate.
3. Complete the physical-device checks below on the exact candidate. If only
   the live URL can be tested, first have the maintainer publish the approved
   candidate to staging; record which build was tested.
4. Review the optional infrastructure audit if returned. Existing Pages
   publishing retains files; do not delete the shared publishing branch to
   solve stale production files because it also contains staging.
5. After publication, verify the served cow/route labels/palette are the new
   candidate, complete a lesson, and reload a project-prefix deep entry.
   Keep a clean desktop browser available for the presentation.

## Real-device check (one iPhone/Safari and one mid-range Android)

Record device, OS/browser, candidate URL, result and a short recording of any
failure. Do not enter a real name; leaderboard aliases remain on that device.

- Fresh entry: enter/skip the film, enable sound by a gesture, mute it, then
  background/foreground. Audio must stop while hidden and mute remain effective.
- Farm: walk, turn, walk forward again; use both sticks together and lift one
  finger. Try Steps as the no-walking alternative.
- Portrait to short landscape and back: controls, lesson text and demonstration
  actions remain reachable without being covered by browser chrome.
- Complete the milk route, including an incorrect placement and Undo. Pause
  cooling, close and reopen; no delayed reward appears after interruption.
- Visit all three places, try optional demonstrations, return to the map and
  revisit. Note visible stalls, heat or crashes; do not infer FPS from screenshots.
- Finish quizzes/certificate, reload and confirm retained progress. Separately
  try reduced motion and the text-friendly route. Capture any screen-reader
  issues when an experienced tester is available.

If a phone fails 3D, use the existing text-friendly route for that device and
report the limitation rather than claiming phone certification. Renderer
context-loss recovery also has automated coverage; physical interruption
behavior still needs observation.

## Content and commercial decisions to chase

- Missing client questions/attachment: keep existing approved-for-review
  content until supplied; do not invent replacement questions.
- Film, logo/photo rights and educator/brand signoff; target learner age.
- Whether the module quote counts this prototype or only additional modules;
  what monthly maintenance includes. A comparable module estimate assumes
  supplied approved content and existing mechanics, not new custom 3D/video.
- Shared leaderboard and inverted look remain deferred. This leaderboard is
  device-local, not a cross-school ranking service.

## Ten-minute presentation route

Enter the map, show the farm and the cow comfort demonstration, use Steps to
show milk-route feedback, then show a processor activity and the market seal
activity. Explain that demonstrations are optional. Use an independently
completed local save to show the certificate if presentation time is short;
do not represent a seeded demonstration as learner completion. Show module
reuse through the authoring guide, without claiming a second module is delivered.
